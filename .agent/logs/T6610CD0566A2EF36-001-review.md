## Blocking Findings

### CR-001: Resolve archived done children when evaluating milestones

- Severity: Major; functional achievement and correctness; introduced integration
  defect in the milestone feature, not a request to fix unrelated archive behavior.
- Evidence: tools/agentctl.py:2731-2738 consults only the live board;
  tools/agentctl.py:2757-2759 consequently refuses closure;
  tools/agentctl.py:5054-5057 reports archived children as missing.
  The existing archive at tools/agentctl.py:11656-11668 moves done entries out
  of the live board into .agent/archive/board.json.
- Reproduction: create M-1 with children E-1 and E-2; finish E-1, let it age
  beyond the archive window, run reconcile archive --days 30, then finish E-2.
  The executable probe seeds explicit done fixture states and runs the actual
  archive CLI, the common done-path cascade, and board --tree. It does not
  fabricate independent approvals.
- Observed: archive contains E-1=done; E-2=done on live board; cascade returns
  []; M-1 remains todo; tree prints M-1 [todo, 1/2 done] and E-1 [missing].
- Impact: a long-running milestone never completes even though all children
  completed, and nested parents remain open. Contradicts the original DoD's
  every-child-done completion and DAG rendering requirements.
- Minimum fix: use authoritative live-plus-archived child resolution for counts,
  cascade and tree, retaining legitimate missing-child detection and locating
  archived completion/gate evidence correctly. An explicit, enforced policy
  retaining referenced children live could also preserve the invariant.
- Verification: archive one completed child, finish the last live child, assert
  recursive parent completion, child-naming completion records, correct tree and
  flat progress; retain archive behavior for unrelated completed tasks.

### CR-002: Preserve concurrent additions to a milestone's deps

- Severity: Major; correctness and data integrity; exposed by the new shared
  mutable --parent field (not a general rewrite of the existing merge driver).
- Evidence: tools/agentctl.py:5180-5186 adds children by mutating the parent's
  deps. Existing tools/agentctl.py:537-550 resolves a concurrent board entry by
  selecting one whole entry; tools/agentctl.py:861 invokes this resolver.
- Reproduction: shared base M-1 has deps=[]; checkout A creates E-1 --parent M-1,
  checkout B creates E-2 --parent M-1. Merge the resulting board ledgers using
  the production three-way merge driver, with B's parent timestamp newer.
- Observed: merge reports no conflict; both child rows survive but M-1.deps is
  only [E-2]. With E-2 done and E-1 still todo, the cascade closes M-1.
- Impact: sync silently forgets required work and records a prematurely completed
  milestone, directly violating the DoD goal of parallel leaves under a root.
- Minimum fix: merge independent dependency additions with base-aware semantics,
  or represent parent edges as independently mergeable records. Conflicting
  removals/reopens and merged cycles must not be silently accepted.
- Verification: two-clone concurrent --parent additions survive sync in both
  orders; first approval cannot close the parent, last approval does; completion
  names both children. Include update-versus-close and cycle conflict cases.
