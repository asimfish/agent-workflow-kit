## Task Contract

- Goal: Give concurrent conversations hard document-ownership boundaries and scope-aware read receipts so business-scoped workers never need `.agent/` in scope, controller-generated files cannot be hand-edited by agent tool calls, and one task finishing does not invalidate every unrelated session's receipt.
- Non-Goals: Restricting human edits, changing session-key derivation, per-task progress logs, automatic splitting of legacy monolithic plans, or altering git hook enforcement for humans.
- Dependencies: T-057/T-059/T-061 identity isolation and fail-closed dispatch (merged in PR #10), existing `sessions guard` path checks, `_hash_docs` receipt store, and the multi-session regression suite.
- Expected Deliverables: (1) `sessions guard` denies direct writes to controller-generated workflow files regardless of scope and auto-allows the active task's own task doc; (2) receipt hashing for `.agent/TASKS.md` ignores other tasks' index rows and for `.agent/PROJECT_PLAN.md` ignores the Change Log body and other tasks' checklist rows; (3) a four-conversation concurrent end-to-end regression mirroring the ChemBench scenario; (4) concise documentation of the ownership model in the workflow entry (source + template), README, and enforcement reference.
- Definition of Done: New regressions fail before the implementation and pass after; the full suite passes; direct agent writes to board/TASKS/state/logs/gates/loop-runtime files are blocked with actionable messages; a business-scoped worker can edit its own task doc; an unrelated task finish no longer blocks other sessions' writes while plan-body and own-row changes still do; an independent reviewer approves via gate.
