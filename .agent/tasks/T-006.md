## Task Contract

- Goal: let custom (non-built-in) loop contracts declare executable check commands that `agentctl loop run <id> --once` actually runs, deriving the run status from exit codes, so projects can add project-specific loops without editing agentctl.
- Non-Goals: cron/daemon scheduling; parallel loop execution; unbounded or interactive commands; automatic fixes for failing checks.
- Dependencies: loop runtime (T-002/T-003) and feedback link (T-005); previous-state injection and checkpoint follow-up packets must keep working for custom loops.
- Expected Deliverables: agentctl support for a machine-readable command block in loop contracts (with per-command timeout and output capping), updated `docs/loop-engineering.md`, an example custom loop in installed templates.
- Definition of Done: a custom loop with declared check commands runs via `loop run <id> --once`, its report reflects command results and carries a `Previous:` line; a failing command yields `failed`/`partial` and feeds checkpoint follow-up packets; `agentctl check --mode manual` passes.
