## Task Contract

- Goal: Add a deterministic project-level evaluation layer that lets a trusted supervisor run the same verifier suite against baseline and candidate worktrees, compare held-in and held-out results, and persist an auditable accept/reject decision.
- Non-Goals: No LLM judging, automatic harness edits, evolutionary search, private benchmark hosting, scheduler installation, generic background job manager, candidate merge, or cryptographic protection from a repository owner.
- Dependencies: T-023 provides crash-safe bounded execution patterns; T-024 provides isolated candidate worktrees; existing task and Git gates provide the trusted supervisor workflow.
- Expected Deliverables: A versioned eval-suite schema; `eval list/run/show/compare/gate`; supervisor-owned target execution with argv-only commands, timeouts, bounded output, suite hashes, commit/dirty evidence, split metrics, and durable reports; a starter suite and documentation; fresh-install regressions.
- Definition of Done: From a fresh installed project, a supervisor can evaluate two target checkouts with one unchanged suite, observe held-in and held-out scores, reject a candidate that regresses either split or fails a required case, accept a non-regressing candidate, reject mismatched/tampered suite evidence, and reproduce the decisions from persisted JSON reports with all repository gates passing.
