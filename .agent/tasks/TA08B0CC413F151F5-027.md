- 2026-09-02 22:20:00 Root cause of the unclaimed-lease case: `run start` spawns the supervisor with `Popen` and never reaps it while waiting; a supervisor that dies before claiming is a zombie, `os.kill(pid, 0)` succeeds and the birth marker still matches, so `_await_supervisor_claim` returned "pending" after 30s instead of "died" and the replacement spawn never ran. Verified empirically on macOS (`_pid_alive`/`_same_process` both True for a zombie child).
- 2026-09-02 22:40:00 Fix: `_await_supervisor_claim(..., process=supervisor)` returns "died" when `process.poll()` is not None; `_pid_alive` consults `/proc/<pid>/stat` state `Z` on Linux. Watchdog tests: idle/grace/kill windows 1s, sample 0.05s, deadlines 30s, payloads outlive supervisor start-up, failures dump supervisor logs. Lease suite: 28 passed normally.
- 2026-09-02 22:55:00 With deaths now visible, a 4-round stress run failed fast at `run start` and the supervisor log showed the real cause: `agentctl _run-supervise: error: argument --token: expected one argument`. `secrets.token_urlsafe(32)` begins with `-` in 1/64 draws (measured 3114/200000) and argparse treats `--token -...` as a missing value. Every such `run start` spawned a supervisor that died at argparse, then (pre-fix) reported success after 30s with a run that never launched. Fix: `secrets.token_hex(32)` plus `_supervisor_argv()` attaching `--root=/--lease=/--token=` with `=`; regression test round-trips leading-dash tokens through `build_parser()`. Lease suite: 29 passed.
