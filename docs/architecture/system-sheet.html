D

任务验收 · 主路径与责任分离

这是常用主路径，非完整状态机。失败测试阻止 finish；blocked / approved 等分支见规范。Milestone 只组织子任务，不能领作执行任务；最后一个子任务批准后自动闭合。

D 依据：cmd_complete · _cmd_gate_unlocked · _cascade_milestones

E

反馈闭环 · 六环节与下一轮

  1. 1 · Trigger / 触发work-start / pre-finish / post-finish；显式监测或外部调度。
  2. 2 · Execute / 执行已授权 worker 推进任务；loop 执行内置检查或声明的命令。
  3. 3 · Check / 检查合同、测试结果、文档一致性、实验声明输出与运行结果。
  4. 4 · Feedback / 反馈失败生成 follow-up；持续失败升级 / 阻断，不能机械重试。
  5. 5 · Memory / 记忆任务文档、loop report / state 保存结论；按任务过滤反馈与缓存。
  6. 6 · Next / 下一轮有限 cycle / 安全 resume / 下一 checkpoint；满足停止条件就停。

不是常驻自主服务：cycle 有界且协作式停止；无内置 cron 或无限 LLM 调度。下一业务任务仍由 agent 再次 work；周期唤醒需外部调度。

E 依据：_run_loop_checkpoint · _create_loop_follow_up · _loop_context_key · _loop_resume

F

失败边界 · 拒绝、恢复与非目标

情形处理 / 不作的保证
计划或本任务文档改变重读 + refresh；同伴任务行变动不要求全员刷新。
身份复制 / claim 被撤销拒绝写入；refresh / rebind 不能恢复所有权。
会话失活 / 后台进程仍活租约与输出仍需检查；不因心跳超时自动转移任务。
执行结果未知 / 中途崩溃禁止自动重放；核实进程与副作用后 ack-inflight。
协议升级先升级屏障、排空旧写者，再迁移并 rebind。
另一台机器 / 独立 cloneGit sync 传账本，live identity 不同步；不是实时分布式锁。
绕过 hooks / 不受信任代码不是 OS sandbox。分支保护、权限、容器仍是外部职责。

可选 supervisor guidance / transport 不等于默认能遥控任意会话。图纸描述现有机制，不宣称所有组合均已实机验证。

F 依据：_check_receipt · _session_claim_error · _upgrade_command_error · 升级规范

设计判断：身份、任务、文档、进程与资源的归属要连贯；本地协调和跨机同步不能混为一谈。图中的职责划分不是已经拆开的 Python 包，控制器仍是主要维护集中点。
